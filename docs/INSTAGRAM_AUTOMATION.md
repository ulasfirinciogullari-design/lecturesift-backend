# Instagram automation (studio Reels, carousels, replies)

This release adds three things to the scheduled Instagram job. All of them are off until the
flags below are set.

| What | Module | When |
|---|---|---|
| Narrated 1080x1920 Reel | `lecturesift/studio_social.py` + `lecturesift/reel_studio.py` | daily from `INSTAGRAM_REEL_HOUR` (default 11, Europe/Istanbul) |
| 5-slide 4:5 carousel of the same lesson | same | daily from `INSTAGRAM_CAROUSEL_HOUR` (default 19) |
| Replies to comments and DMs | `lecturesift/instagram_replies.py` | every timer run |

The timer (`deploy/lecturesift-instagram.timer`) now runs every 15 minutes. Publishing is
idempotent per day and slot (caption markers plus the stored post record), so most runs only
answer messages. Lesson scripts and replies use OpenAI `gpt-4o-mini`; narration uses ElevenLabs.
No Gemini is used.

## Runtime variables

Add to `/etc/lecturesift/runtime.env`:

```text
INSTAGRAM_STUDIO_ENABLED=true
INSTAGRAM_REPLIES_ENABLED=true
ELEVENLABS_API_KEY=<key>
ELEVENLABS_VOICE_ID=<Turkish voice id>
# optional
ELEVENLABS_MODEL=eleven_multilingual_v2
INSTAGRAM_REEL_HOUR=11
INSTAGRAM_CAROUSEL_HOUR=19
INSTAGRAM_REPLIES_DAILY_LIMIT=120
```

## Open decision: the Instagram role environment

The scheduled job runs with `/etc/lecturesift/instagram.env`, generated by
`deploy/generate_role_envs.py`. Its `INSTAGRAM_KEYS` allow-list deliberately excludes
`OPENAI_API_KEY` and the `S3_*` credentials, and `tests/test_role_env_isolation.py` asserts that.

The new job needs, in that role: `OPENAI_API_KEY`, `ELEVENLABS_API_KEY`, `ELEVENLABS_VOICE_ID`,
`ELEVENLABS_MODEL`, the `S3_*` storage settings (rendered media and reply state live under the
`social/` prefix that the API serves), and the new `INSTAGRAM_*` flags above.

The existing `generated_reels.py` path already reads `OPENAI_API_KEY` and social storage too, so
with the current allow-list the daily Reel cannot be produced on the VPS either (inferred from the
code, not observed in production logs).

This PR does **not** widen the allow-list, because that is a least-privilege decision for the
owner. Options, from narrowest to simplest:

1. A storage credential scoped to the `social/` prefix (`SOCIAL_S3_*`) plus a dedicated OpenAI
   project key for social, added to `INSTAGRAM_KEYS`.
2. Add the keys listed above to `INSTAGRAM_KEYS` and update the isolation test.

## Meta permissions

Publishing already works with the current token. Replies additionally need the
`instagram_business_manage_comments` and `instagram_business_manage_messages` permissions on the
Instagram-login token, and the account's "Allow access to messages" setting. Without them the job
logs `Instagram comments unavailable` / `Instagram messages unavailable` and keeps publishing.

## Checks before enabling

```bash
# Draft replies without posting anything
docker compose --profile jobs run --rm instagram python -m lecturesift.instagram_replies dry-run
# Render today's Reel and carousel into storage without publishing
docker compose --profile jobs run --rm instagram python -m lecturesift.studio_social prepare $(TZ=Europe/Istanbul date +%F)
# Then open https://api.lecturesift.com/instagram/studio/<day>/reel.mp4
```

A local preview with the bundled sample needs no credentials (silent without ElevenLabs):

```bash
python -m lecturesift.reel_studio preview /tmp/studio-preview
```
